# Permission commands and audit evidence

[GEN-738](https://doolin.atlassian.net/browse/GEN-738) exposes the existing
discovery, auditor, planner and executor through `exe/jira_permissions`.
Run commands from the repository root with `bundle exec`.

## Connections

Discovery uses JiraTK's existing private administrator configuration.
Audit, plan and execute additionally require `--service-url-env NAME`
and `--service-token-env NAME`. These are names of environment variables
containing the service endpoint and Bearer token, not credential values.
They have no defaults and never fall back to administrator credentials.
The existing HTTPS endpoint, identity and site checks still apply.

In the examples, `SERVICE_ENDPOINT_CONFIG` and `SERVICE_TOKEN_CONFIG`
are placeholder variable names; substitute the names from private setup.
`SERVICE_ACCOUNT_ID` and `SERVICE_GROUP_ID` are immutable IDs to verify.
No command accepts a token value as an option.

## Inspect and audit

```sh
bundle exec exe/jira_permissions scheme --project PAH
bundle exec exe/jira_permissions grants --scheme 10003 --permission ASSIGN_ISSUES
bundle exec exe/jira_permissions audit --account-id SERVICE_ACCOUNT_ID \
  --service-url-env SERVICE_ENDPOINT_CONFIG --service-token-env SERVICE_TOKEN_CONFIG
```

Scheme output includes the normalized grants. Grant listing returns all
grants unless an exact permission filter is supplied. Both print JSON.
The audit prints the fixed six-column matrix by default; `--format json`
prints the same allowlisted report evidence as `AuditReport#to_h`.

Audit defaults to the full administrator-discovered inventory, with PAH
as the positive control and every other project as a negative control.
`--projects PAH,GEN` selects a subset, which is always reported incomplete.
Unknown cells remain unknown; a denied request is never a false permission.
See [audit scope and evidence](permission-audit.md).

Every report generated by the audit command is saved, including mismatch
and incomplete reports. The default is `audit-results.md` at this checkout's
root, regardless of the current directory. `/audit-results.md` is ignored
by Git. `--audit-output PATH` selects another destination; relative paths
are relative to the command's current directory. Parent directories must
already exist. Installed-gem users should select a writable destination.

The Markdown contains the matrix and JSON evidence: actual status, verified
account and site fingerprint, timestamp, scope, project coverage,
mismatches and unknown/error categories. It contains the same allowlisted
data as the report, without credentials, configuration, headers or raw
responses. Each successful save replaces the previous report with a private
file (mode 0600), using a flushed temporary file and a same-directory rename.
An interrupted write or failed rename leaves the previous report intact.

Storage failure is reported on stderr and causes exit 2. Stdout still
contains the observed audit result; storage failure never changes a mismatch
into a pass or rewrites the audit status. Identity or discovery failures
that prevent report creation leave the previous file intact and print no
new report. Check the exit status and timestamp before using saved evidence.

## Review and execute the ASSIGN repair

The only planning operation currently exposed is `pah-assign-repair`.
Its [preconditions and narrow scope](permission-plans.md) are unchanged.
`--broad-holder-json` is required: pass JSON `null`, `""`, or a named JSON
string according to the exact normalized application-role identity found
during inspection. These values are distinct; the CLI does not infer one.

For example, **only if inspection establishes a null holder identity**:

```sh
bundle exec exe/jira_permissions plan --operation pah-assign-repair \
  --account-id SERVICE_ACCOUNT_ID --service-group-id SERVICE_GROUP_ID \
  --broad-holder-json 'null' --output reviewed-plan.json \
  --service-url-env SERVICE_ENDPOINT_CONFIG --service-token-env SERVICE_TOKEN_CONFIG
```

The plan is printed as JSON and saved to a new file with mode 0600. An
existing output file is refused so a reviewed plan is not overwritten.
The default shared-project scope is GEN and PAH; `--projects` can explicitly
include additional reviewed associations, subject to the planner's checks.

Review the complete saved plan, then preview it against current Jira state:

```sh
bundle exec exe/jira_permissions execute --plan reviewed-plan.json \
  --service-url-env SERVICE_ENDPOINT_CONFIG --service-token-env SERVICE_TOKEN_CONFIG
```

After the operator approves that concrete plan, repeat with `--apply`.
The CLI loads that exact saved plan and delegates to the existing executor;
it does not regenerate the plan or extend its scope. Preview and apply print
the execution result as JSON, including failed and uncertain steps. Audit
persistence belongs to the audit command; plan checkpoint evidence remains
in the plan and execution JSON. Run the audit command after execution to
save the current complete matrix and reveal remaining isolation work.

The executor's [concurrency and recovery limits](permission-execution.md)
still apply. Each process starts without earlier in-memory results, and
execution receipt JSON cannot be loaded. Inspect and resolve an uncertain
prior write before another apply. The repair's success does not establish
full PAH isolation. Wider planning and raw grant-write commands are not
exposed by this increment.

## Exit statuses

| Code | Meaning |
| --- | --- |
| 0 | Discovery, plan or execution succeeded; full audit passed |
| 1 | Complete audit found mismatched controls; report is saved |
| 2 | Invalid input, configuration, identity, precondition, incomplete audit, or file failure |
| 3 | Execution stopped after attempting a write; inspect its JSON evidence |

Help needs no credentials. Unknown, repeated, abbreviated, missing or
inappropriate options are rejected before the operation. `--apply` is
accepted only for execute. File and parse errors omit argument values.

## Replaceable audit storage

`Auditor` and `AuditReport` remain independent of storage. The CLI invokes
`Persistence#save(report)`, which delegates to an injected adapter:

```ruby
require 'jiratk/permissions'

store = JiraTk::Permissions::Persistence.new(
  adapter: JiraTk::Permissions::MarkdownFile.new(path: '/chosen/existing/directory/audit.md')
)
store.save(report)
```

An alternate adapter implements `save(report)` and raises a sanitized
`JiraTk::Permissions::Error` on failure. Inject the interface into
`JiraTk::Permissions::Cli.new(persistence: store)` when embedding the CLI;
require `jiratk/permissions/cli` for that class. The injected store takes
precedence over `--audit-output`. No database backend is implemented.

Synthetic HTTP integration tests exercise these commands through the real
library, plus executable exit codes and filesystem failure cases. Run
`bundle exec rspec`, `bundle exec rubocop`, and the dependency audit.
